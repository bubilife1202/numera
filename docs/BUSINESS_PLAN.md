# 수학 학습형 RPG 게임 "MathQuest (가칭)" 사업 기획서

**작성자**: Jules (30년차 프로그래머, PM, 개발자)
**작성일**: 2024년 5월 21일
**버전**: 1.1 (수정: 서버 비용 제로화 아키텍처)

---

## 1. 개요 (Executive Summary)

### 1.1. 비전 (Vision)
"게임을 해도 공부가 된다"는 부모님의 니즈와 "공부도 게임처럼 재미있어야 한다"는 아이들의 니즈를 동시에 충족시키는, 에듀테크(Edu-Tech)와 게이미피케이션(Gamification)이 결합된 최고의 수학 학습 플랫폼을 구축한다. 초기 운영 비용을 최소화하여 지속 가능한 서비스를 지향한다.

### 1.2. 목표 (Mission)
단순한 퀴즈 풀이 형식을 탈피하고, 메이플스토리나 히어로즈와 같은 정통 RPG 요소를 도입하여 사용자의 몰입도를 극대화한다. 웹 기술 기반으로 개발하여 PC와 모바일 어디서든 접근 가능한 크로스 플랫폼 환경을 제공하며, **Serverless 아키텍처**를 통해 고정 비용을 0원으로 만든다.

---

## 2. 시장 분석 및 타겟 (Market Analysis & Target)

### 2.1. 타겟 오디언스 (Target Audience)
1.  **핵심 사용자 (User)**: 초등학교 고학년 ~ 중학교 3학년 (10세 ~ 16세).
    *   RPG 게임의 성장 요소(레벨업, 아이템 파밍)를 선호함.
    *   단순 반복 학습에 지루함을 느낌.
2.  **핵심 구매자 (Buyer)**: 학부모 (30대 후반 ~ 40대).
    *   자녀의 스마트폰 사용 시간을 걱정함.
    *   학습 효과가 증명된다면 유료 결제 의사가 높음.
    *   자녀의 학습 현황을 데이터로 확인하고 싶어함.

### 2.2. 기존 시장의 문제점
*   기존 수학 게임은 단순한 사지선다형 퀴즈의 나열에 불과함.
*   "게임"이라기보다는 "숙제"에 가까운 UI/UX로 인해 아이들의 자발적 참여 유도가 어려움.
*   화려한 그래픽의 상용 게임에 비해 시각적 매력이 떨어짐.

## 3. 서비스 상세 기획 (Product Description)

### 3.1. 게임 컨셉: "판타지 수학 대륙의 모험"
*   **장르**: 횡스크롤 액션 RPG (메이플스토리 스타일) 또는 턴제 전략 RPG (히어로즈 오브 마이트 앤 매직/다키스트 던전 스타일).
    *   *초기 MVP는 접근성이 좋은 횡스크롤 액션 RPG로 기획.*
*   **세계관**: 숫자의 균형이 무너진 판타지 세계. 플레이어는 '수호자'가 되어 몬스터(오류)를 처치하고 세계의 질서를 바로잡아야 함.

### 3.2. 핵심 게임 메카닉 (Core Mechanics)
1.  **전투 시스템 (Math Combat System)**
    *   공격/스킬 사용 시 수학 문제가 제시됨.
    *   **정답 속도**와 **정확도**가 데미지와 치명타 확률에 영향을 줌.
    *   **클라이언트 사이드 연산**: 문제 생성 및 정답 판정은 100% 클라이언트(브라우저)에서 처리하여 서버 부하를 제거함.

2.  **성장 시스템 (Progression)**
    *   **클래스**: 전사(기하학), 마법사(대수학), 도적(확률과 통계) 등 수학 분야별 특화 클래스.
    *   **아이템**: 펜, 지우개, 계산기 등을 판타지적으로 재해석한 장비.
    *   **로컬 저장 우선**: 오프라인 상태에서도 진행이 가능하도록 로컬 스토리지에 데이터를 우선 저장하고, 네트워크 연결 시 클라우드 동기화.

3.  **소셜 요소 (Social) - 비동기 중심**
    *   실시간 서버 비용을 절감하기 위해 실시간 파티 사냥 대신 **비동기 랭킹전** 및 **친구 고스트(AI)와 파티 맺기** 시스템 채택.
    *   길드 시스템: 게시판 형태의 커뮤니티 기능으로 구현.

### 3.3. 학습 관리 시스템 (LMS for Parents)
*   **학부모 대시보드 제공**: 자녀의 플레이 시간, 정답률, 취약 단원 분석 리포트 제공.
*   **데이터 최적화**: 필수적인 학습 데이터만 서버(무료 DB)에 저장하여 스토리지 비용 절감.

## 4. 기술적 구현 방안 (Technical Architecture) - Zero Cost Strategy

"일단 서버비가 들지 않아야 한다"는 요구사항을 충족하기 위해 **Serverless 및 BaaS (Backend as a Service)** 무료 티어를 적극 활용한다.

### 4.1. 프론트엔드 (Hosting: 무료)
*   **호스팅**: **GitHub Pages**, **Vercel**, 또는 **Netlify**의 무료 티어 사용. 트래픽 제한이 넉넉하고 CDN을 통해 전 세계 어디서든 빠르게 접속 가능.
*   **엔진**: Phaser 3 (HTML5 게임 엔진) + React.
*   **앱 패키징**: PWA (Progressive Web App) 기술을 사용하여 별도의 스토어 등록 비용 없이 모바일 앱처럼 설치 가능하게 함.

### 4.2. 백엔드 및 데이터베이스 (BaaS: 무료)
*   **플랫폼**: **Firebase (Google)** 또는 **Supabase**.
    *   **Firebase Spark Plan**: 무료로 인증(Auth), 데이터베이스(Firestore), 호스팅을 제공. 초기 사용자 1만 명 수준까지는 무료 티어로 충분히 커버 가능.
    *   **Supabase Free Tier**: 오픈소스 Firebase 대안으로, 관계형 DB(PostgreSQL)가 필요할 경우 유리함. 월 500MB 저장소 무료.
*   **로직 처리**: 별도의 백엔드 서버(EC2 등)를 두지 않고, **Cloud Functions** (Firebase)을 사용하여 필요한 시점에만 코드를 실행(Serverless). 호출 횟수에 따라 과금되나, 무료 제공량이 매우 많음(월 200만 회 호출 무료).

### 4.3. 멀티플레이어 전략 (비용 절감)
*   **실시간 소켓 서버 제거**: EC2와 같은 상시 구동 서버 비용을 없애기 위해 WebSocket 사용을 최소화.
*   **대안 1 (비동기)**: 리더보드, 우편함, 비동기 PvP(상대방 데이터와 싸우기) 등은 Firestore/Supabase DB만으로 구현 가능.
*   **대안 2 (P2P)**: 만약 실시간 대전이 꼭 필요하다면 **WebRTC (PeerJS)** 기술을 사용하여 클라이언트끼리 직접 통신하게 함. 이 경우 중계 서버(Signaling Server)만 필요하며, 이는 무료 공용 서버를 쓰거나 트래픽이 적어 무료 티어로 해결 가능.

## 5. 개발 로드맵 (Development Roadmap)

### Phase 1: 프로토타입 (1~2개월) - 비용 0원
*   로컬 스토리지 기반의 싱글 플레이 버전 개발.
*   GitHub Pages를 통해 웹 배포.
*   수학 문제 생성 알고리즘 (클라이언트 JS 구현).

### Phase 2: MVP (Minimum Viable Product) (3~4개월) - 비용 0원
*   Firebase/Supabase 연동: 회원가입 및 클라우드 저장.
*   학부모용 리포트 페이지 (웹).
*   안드로이드/iOS 홈 화면 추가 (PWA).

### Phase 3: 확장 및 수익화 (5~6개월) - 수익 발생 시 인프라 확장
*   부분 유료화 모델 도입.
*   사용자 급증 시 Firebase Blaze 요금제(종량제)로 전환 검토 (수익이 서버 비용을 상회하는 시점).

## 6. 수익 모델 (Business Model)

초기 서버 비용이 0원이므로, 사용자가 적을 때도 적자가 나지 않는 구조임.

1.  **광고 (Ads)**: 보상형 광고 (광고 보고 부활하기, 아이템 획득).
2.  **인앱 결제 (IAP)**: 캐릭터 스킨, 치장성 아이템.
3.  **구독 모델**: 상세 학습 분석 리포트는 월 구독료를 받는 프리미엄 기능으로 제공.

---

## 7. 결론 (Conclusion)

본 프로젝트는 **Serverless Architecture**를 도입하여 초기 투자 비용과 고정 유지비(서버비)를 'Zero'로 만드는 린(Lean) 스타트업 방식에 최적화되어 있다. 30년차 개발자의 경험을 바탕으로, 비용은 최소화하되 사용자 경험(UX)과 학습 효과는 극대화하는 고효율 에듀테크 플랫폼을 구축할 것이다.
